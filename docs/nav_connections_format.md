# `.nav_connections` Sidecar Format

*This document was written entirely by AI (Anthropic's Claude) based on automated codebase analysis, with maintainer review. Mistakes that slipped through review are possible — please file an issue if you spot one.*

## Purpose

`.nav_connections` is a plain-text sidecar file that feeds **off-mesh connections** into the daemonmap navmesh build. An off-mesh connection is a directed link between two points on the navmesh that the underlying triangulation does not naturally connect — the bot has to perform a movement primitive (jump, drop, wallrun, jumppad ride, elevator wait) to traverse it.

Daemonmap auto-detects drops, basic jumps, and wallruns from BSP geometry. The sidecar lets you augment those auto-detected connections with hand-authored or scanner-validated entries (typically wallruns, since the auto-detector is conservative).

## Producers and consumers

| Role | Project | File |
|---|---|---|
| **Producer (manual)** | Level designer | hand-edited |
| **Producer (automated)** | [Bot2](https://github.com/RebirthMeow/Bot2) | `codemp/game/ai_bot2_wallrun.c::Bot2_ScanWallruns` |
| **Consumer** | daemonmap | `tools/quake3/q3map2/nav.cpp::Nav_LoadSidecarConnections` |

Discovery: daemonmap looks for `<mapname>.nav_connections` in the same directory as the `.bsp` it's compiling, replacing the `.bsp` extension. The file is **optional** — its absence is not an error.

## Line format

One connection per line. Whitespace-delimited (any run of spaces or tabs). Comments and blank lines are ignored.

```
type  sx  sy  sz  ex  ey  ez  bidir  radius  area
```

Parsed at `nav.cpp:1848` with:

```c
sscanf(p, "%31s %f %f %f %f %f %f %d %f %d",
       typeStr, &sx, &sy, &sz, &ex, &ey, &ez,
       &bidir, &radius, &area);
```

Bot2's writer emits:

```c
"WALLRUN  %8.1f %8.1f %8.1f  %8.1f %8.1f %8.1f  0  %.1f  %d\n"
```

Comments start with `#`. A header line is conventional but not required:

```
# Auto-generated by Bot2_ScanWallruns — map: ctf_kejim
# type      sx       sy       sz       ex       ey       ez      bidir  radius  area
WALLRUN    -512.0    256.0     32.0    -512.0    256.0    320.0    0    32.0    4
```

### Field reference

| Field | Type | Description |
|---|---|---|
| `type` | string ≤ 31 chars | Cosmetic label. Daemonmap reads it but does not act on it (the `area` field drives behavior). Bot2's scanner writes `WALLRUN`; level designers may also use `JUMP`, `DROP`, `ELEVATOR`, `JUMPPAD`. |
| `sx sy sz` | float (Quake units) | Start point in **Quake coordinates** (Z-up). |
| `ex ey ez` | float (Quake units) | End point in **Quake coordinates** (Z-up). |
| `bidir` | int 0 or 1 | 0 = one-way (start → end), 1 = bidirectional. |
| `radius` | float (Quake units) | Activation radius around the start point. The bot triggers the off-mesh primitive when its path reaches within this distance. |
| `area` | int | Polygon area ID baked into the navmesh. Drives bot behavior at runtime. |

### Area IDs

Defined in `tools/quake3/q3map2/nav.cpp` and mirrored in Bot2's `g_navmesh.h`:

| ID | Constant | Meaning |
|---|---|---|
| 0 | (default ground) | Walkable ground; not used in sidecar. |
| 2 | `AREA_JUMP_DROP` | Walk-off ledge; one-way drop. |
| 3 | `AREA_JUMP_BASIC` | Running jump across a gap. |
| 4 | `AREA_WALLRUN_ASCEND` | Vertical wall climb (JKA wallrun). |
| 10 | `POLYAREA_ELEVATOR` | Wait-for-elevator ride. |
| 11 | `POLYAREA_JUMPPAD` | Jumppad launch (multi-tier). |

## Coordinate convention

Quake space (Z-up):
- `+X` = right
- `+Y` = forward
- `+Z` = up

Daemonmap converts internally to Recast space (Y-up) via `TransformPointToRecast()`. **Sidecar coordinates are always Quake-space** regardless of whether daemonmap was invoked with `-meters` — the meters scaling is applied internally during conversion.

## Validation rules

`Nav_LoadSidecarConnections` (nav.cpp:1796) applies these rules:

1. **Field count.** Lines that don't parse to exactly 10 fields are skipped with a warning.
2. **Minimum height gain.** `ez - sz` must be ≥ `WALLRUN_MIN_H_QU = 45.0` Quake units. Lines with smaller `dz` are warned and skipped (likely scanner false positives).
3. **Navmesh snapping.** Both endpoints are snapped to the nearest navmesh polygon within an extent of `±96` (X, Z) and `±128` (Y) Quake units. Lines whose endpoints don't snap are skipped.
4. **Elevator crush avoidance.** If the start point falls inside any `func_door` / `func_plat` travel column, daemonmap nudges it perpendicular to the approach vector in 16 u steps (up to a small bound) until it clears all elevator volumes **and** still snaps to a valid poly. Failure to clear → skip.
5. **Per-poly-pair dedup.** Connections that snap to the same `(startPolyRef, endPolyRef)` pair are emitted only once. Densely-sampled scanner output is safe.
6. **Cross-pass geometric dedup.** After all sources (auto-detected + sidecar) are merged, daemonmap removes geometrically duplicate connections regardless of source.

## Worked example

Suppose a JKA map has a wallrun-able pillar at world XY = `(-512, 256)`, height 320 u, with a 32 u floor at the top. A sidecar entry to mark it:

```
# Pillar wallrun on the red flag side.
WALLRUN  -512.0  256.0   32.0   -512.0  256.0  320.0   0   32.0   4
```

- Start at floor level (`sz = 32`), end at top (`ez = 320`). `dz = 288 > 45` ✓
- One-way (`bidir = 0`); the bot drops from the top by other means.
- Activation radius 32 u — the bot triggers the wallrun when its path is within 32 Quake units of the start.
- `area = 4` (`AREA_WALLRUN_ASCEND`) — Bot2 reads this from the binary navmesh and dispatches its wallrun executor.
